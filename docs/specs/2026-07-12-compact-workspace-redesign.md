# Prompt Hub 紧凑工作台改版设计

日期：2026-07-12  
状态：已确认，待实施计划

## 1. 背景与目标

Prompt Hub 当前采用顶部大导航、24px 外围留白、32px 外框圆角和多层半透明卡片。以 1280×720 实测时，顶部区域占 83px；Seedance2 左侧模板栏和右侧预览共占约 600px，中央编辑区仅约 523px，却需要滚动约 1380px 高度。提示词库、测试台、Seedance2 和设置的主操作位置与页面逻辑也不一致。

本次改版覆盖整个应用，目标是：

- 以 1440×900 为主要设计基准，在较小窗口中保持主任务可用。
- 移除无效留白，把空间优先交给内容与编辑操作。
- 四个页面统一使用相同的导航、面板和操作反馈语法。
- 允许深度调整信息架构，但不改变现有数据库、IPC 和第三方服务协议。
- 保留当前工作区中在建的 Seedance2、多图预览等功能，并在其上适配新布局。

## 2. 已选方案

采用“窄侧边功能轨 + 页面内工作台”方案。

全局界面由三层构成：

1. 58px 左侧功能轨：提示词库、测试台、Seedance2、设置以及底部帮助入口。
2. 48px 顶部命令栏：页面标题、编辑状态、全局/页面搜索和当前页面的主要操作。
3. 页面工作区：按需组合资源栏、主任务区和详情/预览栏。

应用内容铺满窗口，不再使用带 24px 外边距的居中大面板。页面内部可以使用三栏，但右栏只在详情、参数或预览有价值时出现，不机械地为所有页面保留空面板。

## 3. 全局组件边界

新增或重构以下共享界面组件：

- `AppShell`：组合功能轨、命令栏和当前页面，不读取业务数据。
- `NavRail`：负责全局页面切换、激活状态、文字提示和键盘焦点。
- `CommandBar`：通过 props/slots 接收标题、状态、搜索和主要操作。
- `WorkspaceLayout`：组合资源区、主区和详情区，管理断点布局。
- `ResizablePane`：处理面板宽度、最小/最大宽度、折叠与拖动。
- `PanelDrawer`：在中小窗口中承接被折叠的资源栏或详情栏。
- `StatusBadge` 与 `InlineNotice`：统一保存中、已保存、失败与重试反馈。

共享组件只管理布局和通用交互。提示词、生成任务、模板、设置等业务状态继续由各功能页面和现有 Zustand store 管理。

## 4. 页面设计

### 4.1 提示词库

布局：

- 左栏：类型、收藏、最近使用、最近生成和标签筛选。
- 中栏：常驻快速录入带、搜索/排序、提示词卡片列表。
- 右栏：当前选中提示词的详情编辑器。

快速录入必须保持零额外步骤：

- 常驻中栏顶部，不放进命令栏，不使用弹窗。
- 默认约 48px 高，直接输入并使用 `Ctrl+Enter` 保存。
- 聚焦、粘贴多行内容或选择识图时原位展开。
- 保留绘图/LLM 类型、标签、识图和保存操作。
- 失焦且内容为空时恢复紧凑状态。

卡片点击只负责选中；编辑器固定在右栏。自动保存必须显示“保存中”“已保存”或“保存失败 · 重试”，避免用户无法判断修改是否落库。

### 4.2 测试台

布局：

- 左栏：当前提示词、词库搜索和最近使用。
- 中栏：本轮生成结果、并排比较和历史结果切换。
- 右栏：provider、模型、尺寸和高级参数；生成操作固定在面板底部或命令栏。

参数与结果不再混排。生成失败显示在对应任务/结果卡片内，保留输入和已成功结果，不用全局弹窗中断工作。

### 4.3 Seedance2

布局：

- 左栏：模板、片段预设和参考分组，可通过标签切换。
- 中栏：开篇总述、参考、镜头序列和风格等结构化编辑章节。
- 右栏：实时预览和固定的“复制完整提示词”操作。

开篇、参考、镜头和风格使用可折叠章节，并提供粘性章节导航。默认展开正在编辑的章节，避免所有长表单同时占据纵向空间。镜头仍支持排序、复制、删除和保存为预设。

切换模板、新建模板、删除模板或离开页面前，如果存在未保存草稿，必须提供“保存并继续”“放弃更改”“取消”三种选择，不允许静默覆盖。

### 4.4 设置

布局：

- 左栏：AI 服务、视觉模型、图像生成、数据与应用等用途分类。
- 中栏：当前分类的配置表单。
- 右栏：连接状态、用途说明和相关帮助；空间不足时改为抽屉。

常用字段直接展示，高级选项折叠。所有服务配置统一遵循“编辑配置 → 检查必填项 → 保存”的顺序，配置完整性和保存状态常驻可见。本次不发起真实网络探测，因为现有 IPC/provider 协议没有无副作用的连接测试接口；真实连接测试需另行设计，避免用生成请求代替探测并产生费用。

## 5. 视觉系统

保留现有暖白背景和蓝色强调色，但减少玻璃拟态和嵌套卡片：

- 基础间距使用 8、12、16px；仅页面级分组允许 20–24px。
- 控件圆角 7–8px，面板圆角 10–12px。
- 主要界面字号 13–14px，页面标题 16–18px。
- 面板使用实色背景、细边框和轻微阴影，避免多层半透明背景。
- 主要按钮只用于每个上下文的一个主操作；危险操作不与主操作并列强调。
- 面板开合与状态反馈动画为 120–180ms，并遵守减少动态效果的系统偏好。

## 6. 响应式与空间规则

- 宽度不小于 1320px：资源栏、主区、详情栏三栏并列。
- 1024–1319px：优先把右侧详情/预览变为抽屉，保留资源栏与主区。
- 小于 1024px：主任务区独占；资源和详情都由按钮打开抽屉。
- 主任务区始终优先获得剩余宽度，不允许辅助区把主区压到不可编辑。
- 面板支持拖动调整宽度，并记住用户上次设置。
- 面板宽度必须设置合理的最小值和最大值，双击分隔线恢复默认宽度。

## 7. 状态与数据流

数据流保持现有边界：

`用户操作 → 页面草稿/UI 状态 → Zustand 或 preload IPC → Electron 主进程 → SQLite/安全存储/服务调用 → 明确反馈`

- 面板宽度、折叠状态和最后访问页面进入 UI store，并持久化到本地界面偏好。
- 页面业务草稿留在对应功能组件或功能 store，不放入共享布局组件。
- 现有 SQLite schema、IPC bridge 和 AI/image provider 接口在本次改版中保持不变。
- 如果实施中发现必须修改业务协议，应另行补充设计，不在本规格中顺带扩展。

## 8. 错误与反馈

- 字段校验错误紧邻字段显示。
- 保存错误显示在命令栏状态区，并提供重试入口。
- 生成错误显示在对应任务卡片内。
- 连接测试结果显示在相关设置区和状态栏。
- 任何失败都不得清空用户草稿、已生成结果或当前筛选状态。
- 成功提示使用短暂非阻塞反馈；需要用户决定的情况使用明确的三选确认对话框。

## 9. 可访问性与键盘操作

- 功能轨按钮必须有可访问名称和 tooltip。
- 所有抽屉、折叠章节和活动标签暴露正确的 ARIA 状态。
- 分隔线支持键盘调整宽度；面板收起后焦点回到触发按钮。
- `Ctrl+Enter` 保持为快速录入保存快捷键。
- 不以颜色作为保存、错误或激活状态的唯一表达方式。
- 焦点样式在暖白和深色功能轨上都必须清晰可见。

## 10. 验证策略

自动化验证：

- 运行现有全量测试，确保业务行为无回归。
- 为功能轨切换、面板折叠、宽度持久化和抽屉焦点管理新增组件测试。
- 为快速录入的紧凑/展开状态、`Ctrl+Enter`、识图入口和保存反馈新增测试。
- 为 Seedance2 未保存草稿切换保护新增测试。
- 为保存失败重试、生成错误就地展示和连接测试状态新增测试。
- 运行 TypeScript 类型检查与生产构建。

视觉与交互验证：

- 在 1440×900、1280×720、1024×768 三种尺寸检查四个页面。
- 验证窄窗口的面板折叠顺序、抽屉开合和主任务区可用宽度。
- 验证无数据、加载中、长文本、多标签、多镜头和 API 失败等边界状态。

## 11. 非目标

- 不重写数据库或迁移现有用户数据。
- 不更换 Zustand、Electron IPC 或 provider 架构。
- 不新增新的 AI 服务、生成能力或模板字段。
- 不在本次改版中重做悬浮球视觉。
- 不引入新的重量级 UI 框架。

## 12. 完成标准

改版完成需同时满足：

- 四个主页面使用统一的功能轨、命令栏和工作区布局。
- 1440×900 下页面无外围浪费，主任务区明显宽于当前实现。
- 1280×720 下四页仍可完成核心任务，辅助区按规则折叠。
- 提示词库可不经过弹窗或命令栏直接快速录入。
- Seedance2 切换资源不会静默丢失草稿。
- 所有异步主操作有明确的进行中、成功和失败反馈。
- 现有测试、类型检查和生产构建通过，新增关键交互测试通过。
